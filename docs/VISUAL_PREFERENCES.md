# SmartInventoryArrange 视觉偏好分析

整理日期：2026-10-21。根据用户历次看图、盲选和具体修改反馈归纳。

> 目标不是“看起来分类过了”，而是像真人整理：**同样的物品集中成排，组与组摆得规整，空白留得有秩序。**

本文记录审美目标及已经明确的取舍，不代表当前算法全部达到这些目标，也不是一套已经确认的严格字典序或数值权重。安全、合法性及固定规则另属硬边界，不能拿来交换视觉收益。

## 一、同样的物品首先应该放在一起

- 能形成一个连续区域，就不要拆成几块。
- 避免“大部分在左边，另外一两个散落在右边”的尾巴。
- 是否集中，应看实际摆放关系与整体视觉，不只是距离变近或分类分数提高。
- 同物品的连续性不同于宽泛类别的集中；“都属于材料”不等于允许相同物品互相分离。

**历史反馈对应：**代糖果汁出现三横一竖且分开，药品、矿石、啤酒分散，以及三个相同长条物品被拆开，都是明确反例。

## 二、条件允许时优先成排，而不是成列

**物品本身竖放，不等于把同类物品竖着堆成一列。** 几个竖放的物品可以左右并排。

- 同组放得下一排，就优先放在同一排。
- 一排放不下，再使用尽量少的、相邻的换行。
- 换行后仍应看起来属于同一组，不应被其他物品隔开或散落到远处。
- 不应仅为朝向统一，让整个库存充满纵向长列。
- 成排与连续成组需要共同考虑；不是把每件物品放到某一条横线上就算满足要求。

**历史反馈对应：**电池、罐头、奶酪等有条件却没有并排；用户明确纠正了“竖着成列越来越多”的方向。

## 三、行优先，但列边界仍须整齐

用户反对的是“列优先取代行优先”，并不是不要列对齐。

- 相邻行的物品边界尽量对齐。
- 减少上下宽窄变化、不同物品交错插入的参差结构。
- 同尺寸物品形成稳定行列边界，比随意错位更美观。
- 已经形成的整齐行列，不应仅为“分类更集中”而打乱。
- 不把早期“有条件单独成列”的反馈误解成全局永久列优先；后续明确修正为有条件永远优先成排，同时保留边界整齐要求。

## 四、同组方向统一，但允许有规律的互锁拼合

- 普通同类物品尽量方向一致。
- 不喜欢没有明显必要的“三横一竖”、正反混杂或上下错位。
- 枪等不规则物品，如果可以利用真实占格相互嵌合，应当考虑拼在一起形成整齐组合。
- 有规律的交替朝向互锁，不等于杂乱旋转；不能机械地用“方向必须完全相同”否决它。
- 互锁组合本身应保持清晰、可重复的视觉节奏，不应成为任意混向的理由。

**历史反馈对应：**同样的枪明明可以像示例那样互锁并排，却被散落到全图；废弃金属一上一下且方向相反，也被指出不整齐。

## 五、完成大结构后，继续消除可避免的间隔

- 整条行带能够左移时，不应悬在中间。
- 单独一个小组能够向左靠拢时，也不应因为大行带已经贴左就停止整理。
- 平移应保留组内结构，不拆散已成排的物品或互锁组合。
- 不能越过固定障碍、重叠、越界，或为了填缝而破坏更好的分组。

**历史反馈对应：**下半部分整体向左平移，以及催化剂小组再单独向左移动一格。

## 六、中间空洞更少、更小，剩余空白尽量集中到底部

- 减少显眼的中部大洞。
- 减少物品之间零碎、没有必要的空格。
- 同时观察空洞的数量、面积、形状和位置，不能只看空洞数量。
- 不为了局部塞得更紧，换来更多拆组、错行或混乱方向。
- 剩余空白主要在底部形成连续区域，而不是穿插在物品组之间。

**历史反馈对应：**某组 A/B 整体接近，但 A 的中间空洞看起来更小，因此更好。空洞计数下降本身，不足以证明用户会更喜欢布局。

## 七、可移动的容器、机器和大件形成靠上靠左的视觉锚点

- 在允许移动的前提下，容器、机器和大件优先靠前、靠上靠左，形成稳定、规整的视觉锚点，再安排周围小件。
- 整体阅读顺序从上往下，组内顺序从左往右。
- “靠上靠左”不是牺牲同物品连续、同行和方向规律的万能理由。
- 用户曾怀疑整体靠上靠左权重是否过大，但并未确认某个数值一定错误；不能把该疑问写成已确定的权重结论。
- 保留模式下已固定的容器、机器或能量阵列服从原位规则，不因锚点偏好而被移动。

## 八、分类集中不能破坏同物品连续和已有整齐结构

- 同 ItemId 的具体物品组，与食品、材料、机器等宽泛分类区域，应分别看待。
- 分类可以帮助建立秩序，但不能把同物品拆开并交错摆放。
- **保持同类连续，但不为了“分类更集中”破坏已有整齐行列。**
- 不能仅凭某个分类区域分数提高，就认为整体视觉已经改善。

## 九、组内名称和状态排序是另一层要求

- 先形成整齐、合法兼容的槽位，再按已确认的名称和真实状态规则分配实例。
- 酒龄、水质、含量、电量、耐久等指标各有明确语义，不套一套通用“数值大就是好”的规则。
- 不应为了这些内部顺序，重新破坏已经形成的几何结构。
- 此层沿用现有槽位内实例分配策略，不把名称分组擅自升级为全局几何装箱的新硬约束。
- 完整规则见 [组内状态排序规则](SORTING_RULES.md)。

## 十、已经明确的取舍与尚未确定的部分

### 已经明确

1. 有条件成排，不优先堆列。
2. 保持同物品连续，不留散落尾巴。
3. 保留整齐结构，不为宽泛分类指标强行打乱。
4. 利用有规律的互锁，不接受随意混向。
5. 靠上靠左、减少空洞，但这些单项指标不能独自证明整体更好。

### 尚未确定，不能擅自写死

- 所有视觉指标之间完整、绝对的优先级顺序。
- 某个具体权重一定过大或过小，以及应改成的数值。
- 拆组、额外换行、旋转、空洞、边界参差之间固定的数值兑换关系。
- 未见过的新物品组合或新视觉冲突应如何取舍。

这些偏好应共同用于观察实际候选。不能再次仅提高某个单项奖励，就宣称满足了用户审美。

## 十一、优化边界与验证口径

- 物品数量、实例、堆叠、品质、耐久及状态完整保留；不丢失、不复制、不销毁、不错误修改。
- 使用真实占格和合法方向；不重叠、不越界；固定/锁定物品不移动。
- 既有物资箱朝向策略及失败保全行为继续保留。
- “保留容器排列”及其配置生效时，符合内部窗口规则的实例与精确 ItemId=`powerblock` 的能量阵列保持原位置和原方向。
- 保留确定性、主线程原生对象访问边界、快照复核、事务提交和完整回滚。
- 允许在约束内全局重排，不应把“现有布局恰好如此”当成无法形成更整齐分组的理由；但这不是在本文件中要求立刻重构算法。
- 当前进一步探索以视觉质量为重点，不把早先的 400ms 当作唯一筛选目标；这不等于授权游戏内无限搜索或忽略卡顿，运行预算需要单独验证。
- 必须区分“没生成好候选”“生成后选错”“原生应用失败”。离线渲染、分数与测试不能替代实际游戏验证。

## 十二、逐图检查清单

- [ ] 相同物品是否仍有不必要的散落尾巴？
- [ ] 能成一排的组，是否被排成纵列或拆到不同位置？
- [ ] 必须换行的组，是否使用少量相邻行且仍然连续？
- [ ] 普通同组方向是否一致？互锁是否有规律、可解释？
- [ ] 行列边界是否对齐，是否存在交错插入造成的参差？
- [ ] 整条行带或小组是否还有合法、保持结构的左移空间？
- [ ] 中间空洞是否显眼，剩余空白是否尽量连续地留在底部？
- [ ] 可移动的大件/容器/机器是否形成合理的顶部左侧锚点？
- [ ] 是否为宽泛分类分数牺牲了同物品连续或原有整齐结构？
- [ ] 是否完整保留实例状态、固定物品及已有排序规则？

**最终概括：用户偏好的是“完整、横向、规整的物品组”，而不是“局部紧凑但彼此穿插的物品堆”。**
