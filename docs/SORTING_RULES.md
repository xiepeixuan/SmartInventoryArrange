# SmartInventoryArrange 已确认的组内排序规则

版本：v3.17.9；规则记录与实际游戏验收状态分开。

## 一、边界与总顺序
- 保留现有分类、装箱、候选生成和评分策略，不以此功能重新排布槽位。
- 仅在同 ItemId、合法占格兼容的已有槽位之间交换真实实例；固定/锁定物品不动。
- 同 ItemId 内先按当前完整显示名称分组；名称按 Ordinal 升序，不按拼音或售价。
- 下列状态顺序在同名组内生效，最终按槽位从上到下、从左到右体现。
- 每类物品使用其语义规则，不使用一套通用数值权重，不拿价格、序列号、临时缓存、所有权做质量比较。
- 已确认指标全部相同，按稳定实例标识决胜。uniqueId 为0或重复时不作为唯一实例依据；原生地址只匹配对象，不决定顺序。

## 二、分类规则
### 酒
1. 成品 → 发酵中 → 空瓶。
2. 同名成品：实际陈化天数降序，酒龄大的在前。
3. 同名发酵中：剩余发酵时间升序，快完成的在前。
4. 不擅自以酒质或售价抢在已确认指标之前；其余相同按稳定标识。

### 水瓶、桶装水等装水容器
1. 实际水质按原版明确档次从好到差分组。
2. 同一水质档次按实际含量降序；基础水内部不让微小污染差异抢在含量前。
3. 空容器放最后；真实0与状态缺失必须区分。
4. 正确识别 LIQUID_CONTAINER_TAG，不能只接受 CHEM_ITEM_TAG。

### 食物、水果
- 新鲜的在前，不采用“临期先用”。
- 新鲜度档次优先；映射原版与Mod状态时要核实含义，不用未知数值猜方向。

### 电池、耐久用品、多次使用用品
- 电量、耐久、剩余次数统一按绝对剩余量降序。
- 即使同ID最大容量不同，也不改用百分比。

### 药品、化学品、其他液体
- 同名同用途，先品质/纯度，再含量。
- 不把不同用途/内容物当作同一条纯度数值比较；用途先分组，不能让大量低品质物品抢在少量高品质物品前。
- 金属锭按明确纯度等级比较，不按 INGOT_PURITY_* 字符串字典序或默认数字0排序。

### 武器、模组、机器
- 暂时只按名称和完好状态排列。
- 不擅自决定火力、精度、后坐力、性能、效率、质量等多属性优先级。
- 不按机器生产进度或背包内部物品多少排列，不递归改动内部物品。

## 三、鉴定与其他状态（2026-10-18 用户修订）
- 排列忽略鉴定状态，统一按真实状态排序，不使用伪装品质。
- 只读取状态，不改变游戏内已鉴定/未鉴定/揭露/发现标记。
- 不再将未鉴定物品单独分组，不让鉴定标记屏蔽含量、酒龄、耐久等排序字段。
- “忽略鉴定”只影响排列决策，并不使物品在游戏内变为已鉴定。
- 对确有这些状态的物品：未过期/可用优先，再考虑未开封、无锈蚀、无凹损。
- 缺失与真实0、空容器是不同状态；缺失不当作0、正常或已有有效品质。
- 完全不适用的状态不添加默认评分；未映射Mod字段保留诊断，不自行猜测。
- 空容器仍按空容器规则处理；真实状态相同时按稳定实例标识决胜。

## 四、安全和确定性
- 只读取名称和状态，不改酒龄、含量、耐久、品质、堆叠或任何实例数据。
- 物品数量与实例守恒，不丢失、不复制、不销毁、不跨ID交换槽位。
- 仅主线程读取Unity/IL2CPP；工作线程只处理捕获的不可变托管值。
- 名称、鉴定状态、相关状态、成员或姿态在求解期间改变时，拒绝过期结果。
- 保留事务校验、原生合法旋转、失败恢复完整快照；排序不依赖随机数、字典枚举或对象地址。
- 无完整合法候选时保留原回退行为，不借组内排序修改回退布局。

## 五、新状态与验收
- 新Mod/新状态无法映射到以上已确认规则时，向用户询问，不自行猜测。
- 静态测试、离线回放、构建、安装和游戏内验证分别记录，不混写为游戏通过。
- 本次修改先构建并测试，不自动覆盖游戏DLL；每次安装后停止，由用户验证。

## 六、物资箱朝向（v3.17.7 起）
- 智能排列时，SUPPLY_CRATE物资箱只允许原生默认横向方向0，不尝试旋转。
- 箱子可移动位置；固定/锁定箱子仍保留原位原方向。
- 其他物品允许方向、分类、状态排序、评分与搜索策略不变；实际坐标/最终朝向可随整体装箱变化。
- 原始快照不改；横向无完整解时保留原回退行为，绝不丢物品。
- 不改游戏原生旋转能力，不限制玩家手动旋转；缺少合法默认横向的非标准箱子拒绝本次捕获而不猜方向。

## 七、保留容器排列（v3.17.8）
- 原“智能排列”保留普通行为；其下增加“保留容器排列”。
- 仅新入口且 `[SmartInventoryArrange] KeepContainers=true` 时，对 `item.contentWindow != null` 的实例增加固定障碍规则，原位置与原方向不变。
- 不按类别判断，不要求非空，不要求内部窗口正在显示；原生锁定等固定规则继续有效。
- 该模式已固定的物资箱保持当前实际方向，优先于可移动物资箱横向规则。
- 资格变化取消过期提交；提交后固定件变化进入原事务回滚。配置关闭不增加本固定规则。

## 八、能量阵列保留（v3.17.9）
- 仅保留入口且 KeepContainers 开启时，精确 ItemId=`powerblock` 的能量阵列也成为固定障碍；即使内部窗口为 null，原坐标和朝向也不改变。
- 不按名称、分类、前缀或模糊匹配；普通智能排列、配置关闭和其他机器的规则保持不变。
- 原有实例状态、快照校验、事务/回滚机制不变。
