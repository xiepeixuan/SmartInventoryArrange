# 真实日志布局对比：来源与边界

## 这三组是什么

- 右图：2026-10-15最新会话`26-10-15_17-51-20.log`明确加载SmartInventoryArrange v3.13.0；对应快照Result均为`applied`，主日志记录`Smart arrange success`与`fallback=False`。
- 左图：v3.11时期已归档的游戏实际布局，来自历史Result块；24×10为`kept-original`，另外两例为旧Mod的`applied`结果。`kept-original`只证明当次Mod保留布局，不证明布局由游戏原版排序产生。
- 两侧逐一核对宽高、物品`ItemId`多重集合和占格总面积。不同时间的日志未提供可跨会话验证的实例ID与完整状态，因此不据此证明相同容器实例、品质、堆叠、耐久等完全相同。
- 图像是**真实日志坐标的离线重绘**，不是游戏截图，也没有重新运行算法替换右图坐标。

## 图像如何还原

1. 读取两个真实Result块的物品标识、坐标、尺寸和游戏方向编号。
2. 取游戏图鉴导出的对应方向占格；若对称形状去重了该数字方向，只对已观察的方向从基础占格旋转恢复，并校验宽高。
3. 使用既有导出清单中精确匹配`spritePath + spriteAtlasPath`的原生精灵；38种图标逐一核对导出SHA256。
4. 校验六个布局不重叠、不越界，前后物品类型计数与总面积一致，面积比例与右图主日志占用率一致。
5. 按同一格大小、同一物品底色、相同图标和绘制规则渲染左右图；底色仅作辅助，不是游戏原有背景色。

占格来自图鉴，不是日志逐实例导出的原生掩码；禁用格和物品完整状态未导出。绘图校验不替代游戏事务与存档测试。

## 结论的边界

- 可以说：这三次v3.13实际应用均有日志记录，右图位置来自这些结果；相同物品在前两例中更集中。
- 不据此说：左图是已确认的游戏自带排序；两图是同次点击的前后；全部存档和Mod兼容性都通过；没有状态日志也验证了品质/耐久等守恒。
- 11×11例展示了大件前置，但右侧留白更大，保留这个取舍而不把它包装成所有指标都改善。
